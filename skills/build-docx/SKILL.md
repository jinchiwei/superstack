# /build-docx

Markdown -> Jin-branded DOCX via pandoc + reference.docx.

## When to invoke

User asks to make a DOCX from markdown for a paper draft, manuscript, lab writeup, or any Word doc that should be in Jin's brand identity.

For neutral/journal-default DOCX (Times/Calibri), the recipient's Word will substitute as needed; this skill produces the source-of-truth in your style.

## Required arguments

- `--input PATH` -- markdown source
- `--output PATH` -- output DOCX path

## Optional flags

- `--double-spaced` -- 2.0 line spacing (journal manuscripts)
- `--sections` -- numbered headings (1, 1.1, 1.1.1, ...)
- `--toc` -- Word's native auto-generated TOC at start (right-click "update field" to refresh)

## Engine

pandoc CLI + a hand-tuned `reference.docx` with branded styles defined.
The reference.docx is regenerated by `make_reference.py` when palette changes.

## Frontmatter

Same YAML frontmatter contract as build-pdf. Pandoc consumes the metadata for title/author/date if present.

## Research-writeup markdown recipe

The same markdown source that produces clean build-pptx decks (see `build-pptx/SKILL.md`) also produces clean DOCX manuscript drafts, with these conventions:

### Frontmatter

Use the shared spec:

```yaml
---
title: "<paper-style title>"
eyebrow: "<PROJECT · STAGE · YEAR>"
subtitle: "<one-line orientation>"
name: "<Author Name>"
org: "<Lab / Affiliation>"
date: "YYYY-MM-DD"
---
```

### Heading hierarchy

- `# H1` → top-level section (Introduction, Methods, Results, Discussion). With `--sections`, becomes numbered 1, 2, 3, ...
- `## H2` → subsection (1.1, 1.2). Auto-styled deeppink.
- `### H3` → sub-subsection, useful for analysis-block labels or stats subcards. With `--sections`, becomes 1.1.1.

### Figure embedding

Place figures in a sibling `figures/` directory next to the markdown and reference via relative paths:

```markdown
![Figure 1. Caption text.](figures/figure_1.png)
```

Pandoc embeds the image at the natural width with the alt text as a centered caption below. For two-column comparison figures, panel them in a single image before embedding.

### Tables

Use pipe-syntax tables for results. Pandoc renders them with the Light Grid Accent 1 docx style (matches build-pptx's `table-with-takeaway` aesthetic):

```markdown
| Test | β | p | Verdict |
|---|---|---|---|
| Thickness | +0.0049 | 0.008 | ✓ survives |
| AT-class | +0.0097 | 6.6e-4 | ✓ unchanged |
```

### Bold + code spans

Use `**bold**` for key findings inline (renders bold), `` `code` `` for variable / column names (renders monospace Geist Mono). Keeps citations easily scannable.

### Image paths — relative to the markdown file

Same rule as build-pptx: relative paths only, anchored to the markdown's directory. Absolute paths may resolve incorrectly across machines (the file moves but the path string doesn't).

## Font embedding (limitation)

v1 does NOT embed Geist fonts in the output docx. Recipients without Geist
installed see Helvetica/Liberation Sans fallback (specified in the style chain).
Future enhancement could add embedding via low-level XML manipulation.

`~/arcadia/superstack/skills/_shared/branding.py`. To update palette: edit branding.py, then re-run `make_reference.py` and commit the new reference.docx.
